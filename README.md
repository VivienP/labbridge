# LabBridge

**Provenance-first experimental-data infrastructure and a fault-aware campaign runtime for
electrochemical R&D.**

An experimental campaign fails in ways an ordinary data pipeline absorbs silently: an instrument
times out before returning bytes, a retry writes a second copy of a result that was already
accepted, a worker dies between uploading a signal and committing the row that describes it, a
source column carries no declared unit. LabBridge records each of those as a durable domain outcome
rather than a log line, so that every accepted scientific value resolves to a retained observation,
to a source checksum or a simulator seed, and to a named analysis version.

Two environments run behind one adapter interface, and are never merged into one scientific
candidate space:

| Environment | `data_origin` | `execution_mode` | What it is |
|---|---|---|---|
| Au–Ir–Rh HER | `observed` | `replay` | A published electrocatalyst dataset, replayed from its archived measurements |
| Enzymatic biosensor | `synthetic` | `simulation` | A seeded phenomenological simulator used for controlled fault and edge-case injection |

They exercise the same infrastructure abstractions. They are not two fidelities of one problem.

Replaying the generated fixture instead of the acquired archive yields `synthetic + replay`
(ADR-010). The replay adapter decides which pair applies from what the landing root contains — a
`fixture_manifest.json` means generated bytes, a `provenance.json` means acquired bytes — never from
a caller-supplied flag, and a root holding both fails rather than preferring one.

## The integrity line

> Observed and synthetic data are never conflated. Every observation and every derived artifact
> carries `data_origin`, `execution_mode`, `environment_id`, and provenance linking it to source
> files or to a seeded simulator configuration. Synthetic output may be exported and visualised,
> but every human-readable and machine-readable representation identifies it as synthetic, and it
> is never described as measured, experimental, or observed.

The simulator embodies modelled relationships taken from the author's own wet-lab work. Its model
class is a mechanistically informed phenomenological simulator: it produces no experimental numbers
and asserts no physical validation. Its scientific contract, including which of its hypotheses still
lack literature support, is in [`docs/SIMULATOR_MODEL.md`](docs/SIMULATOR_MODEL.md).

## The path being built

One complete vertical path is the first objective, ahead of surface coverage:

```text
campaign declaration
  → durable job
  → HER replay
  → retained observation
  → derived metric
  → manifest
  → evidence bundle
  → crash and restart without a lost or duplicated accepted outcome
```

## Architecture

```text
Scientist
   │
   ▼
FastAPI / CLI
   │  commands and queries
   ▼
Application services
   │
   ├──────────────▶ PostgreSQL
   │                campaigns · work items · events · jobs · attempts · outcomes
   │                budget ledger · idempotency keys · object metadata · relations
   │
   ├──────────────▶ Durable worker
   │                    │
   │                    ▼
   │              Environment adapter
   │              ├─ HER replay        (observed · replay)
   │              └─ Biosensor         (synthetic · simulation)
   │                    │
   │                    ▼
   └──────────────▶ S3-compatible object storage
                    raw observations · Parquet exports · manifests · evidence bundles
```

The domain layer holds campaign rules, state transitions, budget arithmetic, canonical
serialisation, and typed scientific quantities, and imports no framework, ORM session, filesystem
path, or cloud SDK. Full architecture in [`docs/SPEC.md`](docs/SPEC.md); accepted decisions and
their consequences in [`docs/ARCHITECTURE_DECISIONS.md`](docs/ARCHITECTURE_DECISIONS.md).

## What runs today

```bash
pip install -e ".[dev]"
docker compose up -d                    # PostgreSQL and MinIO for the integration suite
```

Three commands are registered. A command with no implementation behind it is not stubbed, because a
stub in `--help` is a claim without evidence.

```bash
labbridge fetch-her --record-id 20439519 --dry-run
```

Reads the pinned Zenodo record, writes an archive inventory, and downloads nothing. Without
`--dry-run`, it acquires only explicitly named files, checksums each one, and writes `provenance.json`
beside them in the git-ignored landing root. Source bytes are never edited after landing.

```bash
labbridge inspect-her
```

Opens the acquired archives and writes a versioned dataset inventory recording actual paths, member
tables, and column shapes — so that no later code infers the schema from an article's prose.

```bash
labbridge build-her-fixture
```

Generates an independently produced, schema-compatible fixture with a seeded manifest, letting the
replay adapter be exercised offline without copying source values.

## Evidence status

Each capability carries exactly one status: `planned` (specified, not implemented), `implemented`
(code exists and its relevant local automated tests pass), `demonstrated` (a reproducible artifact
or operational experiment proves it), or `deferred`.

| Capability | Status |
|---|---|
| HER source acquisition, checksums, and landing provenance | `implemented` |
| Licence and data-use gate, resolved only by a recorded decision | `implemented` |
| Archive inspection and versioned dataset inventory | `implemented` |
| Independently generated schema-compatible HER fixture | `implemented` |
| Typed quantities, candidates, observations, outcomes, and derived metrics | `implemented` |
| Canonical serialisation and content-derived identity | `implemented` |
| Campaign, work-item, and attempt state machines | `implemented` |
| PostgreSQL schema, constraints, and first migration | `implemented` |
| HER replay adapter, with origin decided by the evidence on disk | `implemented` |
| Object storage with read-back checksum verification and a pending/committed lifecycle | `implemented` |
| Durable worker, job leases, and heartbeats | `planned` |
| Event append with expected-version concurrency; deterministic state reconstruction | `planned` |
| Transactional budget reservation and consumption | `planned` |
| Evidence bundles and `labbridge validate-artifacts` | `planned` |
| Biosensor simulator and fault injection | `planned` |
| Campaign API, observability, and operator runbook | `planned` |
| Deployment, backup restore, and the seeded fault-injection experiment | `planned` |
| Model-based selection policy beyond a seeded random baseline | `deferred` |

No capability has reached `demonstrated`. Doing so requires a committed, reproducible artifact with
a manifest, and none has been released yet.

## Limitations

- The end-to-end campaign path does not run. The replay adapter and the object store exist, but
  nothing leases a job, records an outcome transactionally, or exports an evidence bundle.
- At-least-once delivery with idempotent effect handling is the intended worker protocol; the
  constraints that would enforce at most one accepted outcome per intended attempt exist in the
  schema, but no concurrent worker exercises them yet.
- The acquired HER archives and the generated fixture are git-ignored. A clean checkout has no data
  until `labbridge fetch-her` or `labbridge build-her-fixture` produces it.
- The integration suite requires the PostgreSQL and MinIO services from `docker-compose.yml`, and
  skips loudly when they are absent rather than passing vacuously.
- No number in this repository comes from a released measurement run. The reliability targets in
  [`docs/FAILURE_MATRIX.md`](docs/FAILURE_MATRIX.md) are acceptance targets, not results.

## Data source

The observed environment replays the Au–Ir–Rh HER dataset published as Zenodo record
[`10.5281/zenodo.20439519`](https://doi.org/10.5281/zenodo.20439519):

> Thelen F, Kim M, Arruda de Oliveira G, Bürgel JL, Schuhmann W, Ludwig A. Dataset — Autonomous
> scanning electrochemical cell microscopy enables rapid exploration of large compositionally
> complex material spaces. Zenodo, 2026. doi:10.5281/zenodo.20439519. Licensed CC BY 4.0.

Redistribution is permitted with attribution and an indication of changes. That permission comes
from a dated decision pinned to the DOI and the declared licence identifier, not from parsing the
record: the parser always yields `unresolved`, and a record that stops declaring that licence
reopens the gate on its own. Boundaries and layer definitions are in
[`docs/DATA_STRATEGY.md`](docs/DATA_STRATEGY.md).
